## Estabilización del recorrido

El recorrido largo original agotó el tiempo al arrastrar filas después de
ordenarlas. El mismo gesto nativo sobre los datos guardados funcionó tras
recargar, con eventos dragstart/dragover/drop/dragend y orden persistido correcto.
El validador espera ahora el orden ascendente antes de capturar las identidades
y amplía la altura a 1400 px para mantener visibles ambos extremos del arrastre.
Las comprobaciones responsive anteriores siguen ejecutándose a 420, 1024 y 1440 px.
Este ajuste no valida el arrastre a través de scroll anidado a 1000 px de alto.

Una segunda pasada falló al leer inmediatamente el campo calculado de cantidad
de cierre. El caso aislado calculó A=30 desde B=60 correctamente. Se agregó una
espera acotada para ese resultado, conservando tanto la aserción como la posterior
comprobación de cantidades persistidas [30,60]. Con estos ajustes el recorrido
completo aprobó 43 comprobaciones sin cambiar código de ejecución ni expectativas.
Los intentos anteriores se conservan como diagnósticos parciales y no se cuentan
como pasadas completas. Revisión independiente de estos ajustes: sin hallazgos.
